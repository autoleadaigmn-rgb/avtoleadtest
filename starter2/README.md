# AutoLead Starter 2.0 — local test lab

This directory is independent of the published demo. It uses Cloudflare Worker code, two isolated local D1 databases, a one-line iframe widget, and fictional Bayline fixtures. The server accepts only `TEST_ONLY` and `SIMULATED` mail. No Cloudflare account or paid resource is needed locally.

Requirements: Node 22+, pnpm 11.25.0. Run `pnpm install --frozen-lockfile --ignore-scripts`, `pnpm test`, `pnpm check`, then `pnpm dev`. Open http://127.0.0.1:8787/ for the lab, http://127.0.0.1:8790/ for the cross-origin one-line installation, and http://127.0.0.1:8790/responsive for narrow widget frames. The local owner button issues a signed fictional test identity only from the loopback development server. Reloading clears the browser token.

The widget script is `<script async src="https://YOUR_APPROVED_WIDGET_HOST/loader.js" data-shop="bayline"></script>`. This is an example, not a deployed URL. A client site's CSP must allow the widget origin for scripts, styles and frames. Add its exact origin to the tenant's parent allowlist. Never place owner membership, secrets or recipient addresses in public configuration.

`pnpm snapshot -- export bayline` writes a fictional local snapshot and deletion ledger to ignored `snapshots/`. Stop the dev server first. `pnpm snapshot -- restore bayline` restores only to ignored `.local/recovery`, requires a ledger newer than the snapshot, and excludes erased requests. Do not restore an old database over newer records. To roll back local code, switch back to `main`; the old demo and CRM are separate. To pause this test intake set `INTAKE_ENABLED` to `false` in the test Worker config and restart. No remote deployment command is supplied.

Before any cloud pilot: obtain explicit approval for resources and any costs; create two fresh D1 databases and apply migration `0001_initial.sql` to each; replace placeholder database IDs; configure a random server-only SESSION_SECRET and a real Google web client ID with verified owner-subject membership; arrange scheduled retention/delivery, monitoring, backup policy and production privacy review. Keep `TEST_ONLY` and `SIMULATED` until a separately reviewed real-data implementation exists. The current code cannot send email or accept arbitrary personal data.

The notification outbox records intent atomically via a database trigger. A local simulated delivery receipt prevents duplicate simulated notifications across retries. A future real email adapter needs provider idempotency/reconciliation; it is not implemented here. Runtime tests use Miniflare with D1 and a locally signed fake Google certificate, and forbid outbound network except the local certificate fixture. Google sign-in with a real account and hosted Cloudflare behavior have not been tested.
